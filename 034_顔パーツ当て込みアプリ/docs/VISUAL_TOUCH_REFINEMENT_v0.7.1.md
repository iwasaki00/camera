# Version 0.7.1 — VISUAL & TOUCH REFINEMENT

## 変更内容

v0.7.0の既存3タブ・Canvas・描画ループを維持して表示と操作を調整した。外部ライブラリ・画像素材・モデルの追加はない。commit・push・公開は実施しない。

### 拡大鏡

- 起動時とテンプレート読込後は、絵画側・カメラ側とも収納する。プレビュー直下の「拡大鏡」でワンタップ表示／収納する。
- 2〜5倍、ドラッグ移動、左右独立の状態を維持する。
- 初回は選択パーツの表示中心から遠い角を選ぶ。以降はユーザーの位置を保持し、プレビュー内へ収める。画面内に収まる余地があれば、表示領域からもはみ出さないよう補正する。
- タブ切替・画面回転ではドラッグを解除し、表示サイズに合わせて再配置する。画像のみの表示でも、スクロール・VisualViewport変更で位置を補正する。
- 収納中は拡大用の映像取得・描画を行わない。収納状態・倍率・ウィンドウ位置はテンプレートに保存しない。

### 全体表示・選択パーツへ寄る

- 「寄る」で選択パーツを中央へ移動し、画像内の余白と回転した枠の外接サイズを考慮して1.5〜4倍の範囲で表示する。絵画とカメラでそれぞれの枠の大きさから倍率を決める。
- 押す前の表示倍率・パン位置を一時保存し、「戻す」で厳密に復元する。「全体」は100%・パンなしへ戻す操作として分けた。
- 寄ったまま別パーツを選ぶと、そのパーツへ寄り直す。戻す先の手動表示は維持する。
- ピンチ、パン、倍率スライダー等の手動操作では寄る状態を解除し、その表示を新しい手動状態として扱う。自動追従中の顔移動に合わせて表示を自動パンする機能は追加していない。
- 変更するのはViewportのみ。画像座標、手動sourceRect、追従補正、色調補正を変更せず、PNG・録画用Canvasに表示倍率を適用しない。

### 完成画面

パーツ選択列、編集モード、枠・ハンドル・拡大鏡と、配置・カメラ編集の設定を隠す。合成モードの既存selectを上部へ移動し、ORIGINAL／NATURAL／COMICを直接選べるようにした。同じ要素を移動するためイベントや録画ロックを作り直さない。

空いたパーツ列の44pxをプレビューへ割り当て、通常のページ高は増やさない。絵画／カメラへ戻ると編集UIが復帰する。選択パーツや保存済みガイド設定を変更しない。

### カメラ・録画・見た目

自動追従ON/OFFと手動／追従状態を、カメラ映像の直前の44pxの操作列へ移した。共通プレビュー枠の中に収めるためカメラ側の枠高を44px減らし、カメラ画像の縦横比は維持した。

録画開始を赤い「● 録画開始」で区別し、録画中は停止と大きい経過時間を示す。完了後は「結果・保存」を先頭の主要ボタンとし、「録り直す」は副操作にする。未保存動画は淡い黄色の背景と線で示す。既存の確認ダイアログ・Blob保持・保存先確認・共有キャンセル処理を使い、新たな確認方式は追加しない。

角丸、余白、選択パーツの強調、無効ボタン、細いスライダーバー、数値の右揃えを統一した。スライダーの入力領域は44pxを維持する。選択部品やプレビュー操作に限って文字選択・長押しメニュー・不要なダブルタップ拡大を抑制し、標準ファイル入力・保存リンク・共有・テキスト入力は維持する。通常の案内文を短くし、エラーや保存の案内は保持した。

## 保存・既存機能との互換性

IndexedDB／ZIPのスキーマは3のまま。`appVersion`の表示メタデータだけ0.7.1へ更新する。4パーツ、手動編集、MediaPipe自動追従、色補正、拡大鏡、ピンチ・パン、PNG、録画、テンプレートの従来の処理を維持する。

録画用Canvasとレコーダーの実装は変更せず、タブ切替でカメラやモデルを再起動しない。映像・音声の外部送信は追加していない。

## 検証

### スクロール量と操作領域

Windows Chrome、画面高844 CSS px、幅375／390pxで、画像未選択時と400×600背景・640×480カメラ入力時を同条件で比較した。設定・診断・PNG保存用画像は閉じ、録画は待機状態。いずれの幅でも同じ結果だった。

| 指標 | v0.7.0 | v0.7.1 |
| --- | ---: | ---: |
| ページ全高 | 893px | 877px |
| スクロール可能量 | 49px | 33px |
| 絵画プレビュー枠 | 434px | 434px |
| 完成プレビュー枠 | 434px | 478px |
| カメラ枠（映像直前の操作列を除く） | 434px | 390px |

スクロール削減効果を維持し、通常の案内文の短縮でさらに16px減った。カメラは共通領域に44pxの操作列を設け、映像の縦横比を維持して収める。完成ではパーツ列の分をプレビューへ割り当てる。設定展開時・録画結果表示時などのページ高は異なる。iPhone実機のSafari UIを含むスクロール量は本版では未測定。

主要ボタン・表示コントロールは44×44px以上、スライダーの入力高は44pxを維持する。基準データは`reports/v0.7.0-layout*.json`、本版の測定は`reports/v0.7.1-layout*.json`に記録した。

画面・タッチの自動検証では375×812、390×844、375×568、844×390、1280×900を使い、横はみ出し、主要部品の44pxの操作領域、サイズ変更後の編集座標を確認する。録画中もタブは切り替えられ、編集はロックされる。

Chrome／Edgeの各タブから生成した動画は、実際のMediaRecorderで録画してブラウザでデコードし、異なる時刻のフレームが変化することを確認した。従来の録画関連テストではさらにMP4 7本、WebM 1本を生成し、ffprobe／ffmpegで再生時間、フレーム変化、音声トラックを調べた。NATURAL音声付き録画ではAAC音声を検出した。これらは動く人工映像・テスト音声による確認であり、iPhoneの実際の発話同期の検証ではない。

顔追従は同梱の実MediaPipeモデル／WASMと静止顔写真の変形入力を使って確認する。権限拒否、共有キャンセル、容量不足、録画開始失敗等にはモック／障害注入も併用する。

Edgeのヘッドレス実行では、録画・画面キャプチャ後にサイズを変更した際、タッチ入力の応答待ちが繰り返しタイムアウトした。入力先は編集Canvasで、開いているアプリのダイアログはなかった。テスト実行を既存の録画テストと同じ前面・フォーカス・バックグラウンド抑制無効の条件へ揃えた再試行ではPASSした。個別の要因は未特定であり、アプリの不具合と断定して構造変更は行っていない。テスト側は予期しないファイル選択画面も検出する。

証跡は `reports/v0.7.1-*.txt`、`v0.7.1-screens-{chrome,edge}.json`、`v0.7.1-chrome-recording.json`。絵画・カメラ・完成のスクリーンショットと、解析した実録画ファイルもreports内に保存する。

## iPhone実機未確認事項・制限

v0.7.0の3タブとスクロール削減はユーザーから実機成功の報告がある。本版の追加変更についてはiPhone Safari実機で確認していない。

1. 拡大鏡の初期収納、指での再表示・移動・倍率変更、縦横回転・Safariの下部UI変化・キーボード表示後の位置。
2. 「寄る／戻す／全体」の分かりやすさ、ピンチやパン後の操作、選択パーツを変えた場合の表示。
3. 完成画面の大きさ、合成モードの操作、カメラ操作列・編集ハンドル・拡大鏡の干渉。
4. 未保存動画の強調と、停止・再生・保存・共有・録り直し確認。実カメラの録画・音声同期は実機で確認する。
5. safe-areaと下部バー、44pxのタップ範囲、実際の写真選択・ZIP選択・保存先での再生。

Windows WebKitには録画・カメラAPIがなく、実録画の確認はChrome／Edgeのみ。ブラウザ自動テストの成功をiPhone実機の成功とは扱わない。

大きなパーツでも寄る倍率の上限・下限を適用するため、パーツ全体が枠内へ収まるとは限らない。画面が小さい場合は縦スクロールが残る。プレビューの見えている部分が拡大鏡より小さい場合、スクロールして表示領域を確保する必要がある。寄った表示は保存しないため、次回起動では全体表示から始める。OSによるページ終了後の未保存動画の復元や「写真」への直接保存は保証しない。

次期候補：実機のフィードバックに基づく表示倍率・拡大鏡配置の微調整、初回だけの短い操作案内。今回は大型機能を追加しない。
