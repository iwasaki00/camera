# Version 0.7.0 — SCREEN REORGANIZATION

## 画面構成

絵画／カメラ／完成の3タブを同じ高さのプレビュー領域で切り替える。PCでも同じ構成と座標系を使用する。

- 絵画：従来の直接移動・四隅の拡縮・回転、表示ズーム／パン、拡大鏡。
- カメラ：切り抜き編集、表示ズーム／パン、拡大鏡、自動追従の切替。
- 完成：同じ合成Canvasを使用し、編集ガイド・ハンドル・拡大鏡だけ非表示。ガイドの保存設定は変更しない。2本指ズームと表示リセットは利用可能。
- パーツ選択は上部の4ボタン。合成ON/OFF・削除は調整パネルへ分離。
- 下部バー：画像読込、カメラ開始／停止、PNG保存、調整、録画開始／停止、経過時間、録画結果。録画完了時には既存の結果ダイアログを優先表示する。
- 調整は初期状態で閉じ、A. パーツ編集、B. カメラ・追従、C. 合成品質、D. 録画設定、E. 詳細・診断・ヘルプに分ける。内容は内部スクロール。PNG保存用の画像も折りたたむ。

ボタンの余白を削減し、主要なタップ領域は44px以上を維持した。透明な画像ファイル入力自身の高さも44px以上。スライダーは44pxの操作領域、文字入力・主要selectは16px。カメラ側の拡大鏡は追従スイッチの下から表示する。safe-areaを下部バーと外周に適用し、高さ500px以下では固定を解除してスクロールで操作できるようにした。

## 切替方式と互換性

`screen-ui.js` は起動時に既存DOMを一度だけ再配置する。タブ切替ではDOMを再生成しない。非表示側も `visibility: hidden` でレイアウト寸法を保持し、`inert` と `aria-hidden` によって非表示側への操作・フォーカスを防ぐ。切替時には進行中の編集ジェスチャーを解除し、ガイドを再描画する。

カメラのMediaStream、video、Canvas、Viewport、モデル、録画機構を再生成・初期化しない。絵画とカメラは独立したズーム／パンを維持し、絵画と完成は同じViewportを共有する。完成では読み取り専用の編集判定を使い、各パーツのガイド設定を書き換えない。

カメラの入力videoは非表示タブの外へ一度だけ移し、従来同様の1pxの入力専用要素として維持する。タブのvisibility／inertが映像デコーダーまで隠さない構成とし、プレビュー用Canvasだけを切り替える。

合成描画ループは表示タブに依存しない。録画は従来どおりクリーンな合成Canvasから録画用Canvasへ転送し、顔検出や色補正を二重実行しない。録画中はタブと調整パネルの開閉だけを従来の編集ロックから除外した。未保存動画の保護・音声取得・保存共有・エラー復帰処理は維持している。

IndexedDB／ZIPのスキーマは **3のまま**。`appVersion` メタデータだけ0.7.0へ更新し、旧テンプレートの配置・切り抜き・追従・色調補正の復元を維持する。タブ位置やパネル開閉はテンプレートに保存しない。外部依存・API・モデルの追加はない。

## スクロール量の比較

Windows Chrome 157、DPR 1、画面高844 CSS px。375px幅と390px幅で測定。詳細設定は閉じ、400×600の同じ背景画像と640×480のカメラ入力を使用した。変更前はローカルv0.6.2の画面ファイルを一時コピーから読み取り、変更後と同じテストサーバー／ブラウザで測定した。画像未選択でも同じページ高だった。

| 指標（両画面幅で同じ） | v0.6.2 | v0.7.0 | 変化 |
| --- | ---: | ---: | ---: |
| ページ全高 | 1,684px | 893px | 791px減、47.0%減 |
| スクロール可能量（全高−844px） | 840px | 49px | 791px減、94.2%減 |
| 絵画とカメラのプレビュー上端の差 | 908.25px | 0px | タブで同じ位置へ切替 |
| 絵画プレビュー枠の高さ | 312.25px | 434px | 約39%増 |
| カメラプレビュー枠の高さ | 約168.8px | 434px | 共通枠へ拡大 |

プレビュー枠は画像を引き伸ばすものではない。画像・映像の縦横比を保ち、枠の中に収めるため余白が生じる場合がある。下部バーは初期表示でも画面内にあり、カメラ編集へはスクロールなしのタブ操作で到達する。設定展開時や録画結果では別のスクロール量になる。iPhone実機のブラウザUIによる表示高の変動は未測定。

測定ファイル：`reports/v0.6.2-layout-baseline*.json`、`reports/v0.7.0-layout*.json`。

Chrome／Edgeの画面テストは実際のCanvasストリームとMediaRecorderを使い、絵画・カメラ・完成それぞれから3本ずつ録画した。録画中に全タブへ切り替え、生成動画をブラウザでデコードし、異なる時刻の映像が変化することを確認した。これらは動く人工入力であり、実カメラ映像のテストではない。

Chromeの既存録画テストはMP4 7本とWebM 1本を生成し、ffprobe／ffmpegで映像・再生時間・フレーム変化・音声を検証した。15秒自動停止は15.040秒。音声ONのNATURALではAAC音声を検出し、音声と映像の開始時刻差は0秒、トラック長の差は約13msだった。これらはPCのテスト入力の結果で、iPhoneの発話同期の証明ではない。

顔追従テストは同梱の実MediaPipeモデル／WASMを使用した。静止顔写真を変形して入力し、Workerとメインスレッド代替の追従を検証した。例外・権限拒否・容量不足・共有キャンセル等の障害経路にはモック／注入を用いた。

## 制限とiPhone Safari実機の確認項目

重大な未解決不具合は自動テスト範囲では見つかっていない。Windows WebKitはiPhone Safari実機ではなく、この環境にはMediaRecorder／Canvas.captureStream／カメラAPIがないため、実録画はChrome／Edgeでのみ確認した。30／60秒の長時間録画は本版の画面変更に対して再実施せず、既存仕様と関連単体テストを維持した。

実機では次を確認する。

1. 公開後のVersionが0.7.0であること（本作業では公開しない）。
2. Safari下部UI、ノッチ、安全領域と操作バーが重ならないこと。ブラウザUI開閉・ソフトキーボード・縦横回転時にも操作できること。
3. 各タブで枠のドラッグ・回転・拡縮、ピンチ・パン、拡大鏡の収納／移動が指で操作しやすいこと。
4. 実カメラのMediaStreamと自動追従がタブ切替で継続すること。発話・まばたき・顔消失と復帰時の状態表示を確認すること。
5. 各タブから15／30／60秒の録画を開始し、途中で切り替えても黒画面や停止がないこと。編集UIが動画に含まれないこと。
6. マイクONで手を叩く・短い音を発する動きと音の同期を再生で確認すること。保存・共有キャンセルでも結果が保持されること。
7. PNG、既存テンプレート、ZIP入出力、実際のファイル選択と保存先での再生を確認すること。

画面高さが小さい場合は縦スクロールが残る。PCの2プレビュー同時表示は採用していない。SafariやOSによるページ終了から未保存動画を完全に復元する保証、写真アプリへの直接保存の保証は追加していない。

v0.7.1候補：実機の操作結果に基づく余白・配色・アイコンの調整、拡大鏡の配置プリセット、設定グループへの短い導線。新しい大型機能や描画方式の変更は次版の前提としない。

commit・push・公開は実施していない。
